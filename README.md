# Secure OTA Platform

차량 소프트웨어 업데이트(OTA, Over-The-Air)를 클라우드에서 **안전하게** 배포하는 플랫폼의 축소판입니다.
인프라를 코드로 만들고, 설계 단계부터 보안을 넣는 것(Security by Design)을 직접 해보는 학습 프로젝트입니다.

> 목표: "클라우드 인프라를 만들 줄 아는 것"을 넘어 **"왜 이렇게 설계했는지, 무엇을 막으려는 것인지 설명할 수 있는 엔지니어"**

---

## 학습 목표

### 전체 목표
| 영역 | 할 수 있게 될 것 |
|---|---|
| 인프라 | AWS 리소스를 콘솔 클릭 없이 **Terraform으로만** 만들고 지운다 |
| 네트워크 | 퍼블릭/프라이빗 망분리를 설계하고, 각 서브넷이 왜 그렇게 동작하는지 설명한다 |
| 보안 | 퍼블릭 노출, 과다 권한, 키 유출 같은 설정 실수를 **배포 전에** 막는다 |
| 운영 | 컨테이너 → 쿠버네티스로 서버를 배포하고, 모니터링과 위협 모델까지 다룬다 |
| 소통 | 설계 결정마다 대안과 트레이드오프(비용, 보안, 복잡도)를 말할 수 있다 |

### 단계별 로드맵
| 단계 | 주제 | 핵심 질문 |
|---|---|---|
| **1단계** (진행 중) | Terraform으로 AWS 기반 인프라 + 망분리 | 업데이트 파일 저장소를 외부에서 직접 접근 못 하게 하려면? |
| 2단계 | 업데이트 API 서버(Python)를 컨테이너화 → 프라이빗 서브넷/쿠버네티스에 배포 | 인터넷에 노출하지 않고 서버를 운영하려면? |
| 3단계 | 펌웨어 서명 검증, mTLS | 업데이트 파일이 변조되지 않았고 진짜 서버에서 왔음을 어떻게 보장하나? |
| 4단계 | 라즈베리파이 = 가상 차량 제어기 에이전트 | 기기는 업데이트를 어떻게 안전하게 받고 적용하나? |
| 5단계 | 모니터링, 위협 모델링 | 공격받고 있다는 걸 어떻게 알고, 어디가 약한가? |

## 1단계 상세 (2026.11.14 ~ 11.28)

### 이 단계가 끝나면 말할 수 있어야 하는 것
- "Terraform으로 VPC를 퍼블릭/프라이빗으로 나누고, 업데이트 파일 저장소를 외부에서 직접 접근할 수 없게 설계했다."
- "IaC 보안 스캔을 CI에 넣어서 잘못된 설정은 배포 전에 막는다."

### 목표 아키텍처
```
VPC (10.0.0.0/16)
├─ Public Subnet  10.0.1.0/24 (2a), 10.0.2.0/24 (2c)   ── IGW, NAT Gateway(테스트할 때만)
└─ Private Subnet 10.0.11.0/24 (2a), 10.0.12.0/24 (2c) ── 업데이트 서버 자리 (2단계)

S3 (업데이트 파일): 퍼블릭 차단 · 암호화 · 버전 관리 · VPC Endpoint로만 접근
IAM: 서버 역할은 해당 버킷 읽기만 (정책에 * 없음)
CI: GitHub Actions — terraform fmt / validate + Checkov
```

### 지금까지의 설계 결정
| 결정 | 이유 |
|---|---|
| 퍼블릭/프라이빗을 **라우팅 테이블로** 구분 | 서브넷 자체에는 퍼블릭 설정이 없음. `0.0.0.0/0 → IGW` 경로가 있는 RT에 연결된 서브넷이 퍼블릭 |
| 퍼블릭 서브넷도 `map_public_ip_on_launch = false` | 실수로 띄운 서버가 자동으로 인터넷에 노출되는 것을 방지 (Checkov `CKV_AWS_130`) |
| 기본 보안그룹 규칙 전부 제거 | AWS가 자동 생성하는 "전부 허용" 그룹을 무력화 (Checkov `CKV2_AWS_12`) |
| CIDR 대역 분리 (1~9번대 퍼블릭, 11~19번대 프라이빗) | IP만 보고 어느 계층인지 알 수 있고, 확장 여유 확보 |
| `default_tags`로 `Project` · `Env` 태그 강제 | 모든 리소스의 소유와 비용 추적 |
| 자격 증명은 `profile` 참조만 | 키는 로컬 `~/.aws/credentials`에만. 레포에는 프로필 이름만 |
| state는 로컬 (`.gitignore` 처리) | 평문 민감 정보가 들어 있어 커밋 금지. 원격 backend(S3 + lock)는 추후 검토 |
| `.terraform.lock.hcl` 커밋 | 팀원과 CI가 같은 provider 버전을 쓰도록 고정하고, 해시로 변조 방지 |

## 디렉터리 구조
```
infra/
  envs/dev/     # dev 환경 Terraform (현재 VPC · 서브넷 · IGW · RT)
  modules/      # 재사용 모듈 (11/20 network 모듈 분리 예정)
server/         # 업데이트 API (2단계)
agent/          # 라즈베리파이 에이전트 (4단계)
.github/        # CI — 보안 스캔 + IaC 스캔 (11/26)
docs/           # 단계별 계획, 아키텍처, 회고
```

## 실행 방법
```bash
# 사전 준비: Terraform >= 1.9, AWS CLI, 로컬 프로필(기본값 "ota")
cd infra/envs/dev
terraform init
terraform plan
terraform apply     # 생성
terraform destroy   # 실습이 끝나면 반드시 삭제
```

## 비용 · 보안 원칙
- AWS 리소스는 **Terraform으로만** 생성, 변경, 삭제합니다.
- 실습이 끝날 때마다 `terraform destroy`. NAT Gateway, 로드밸런서, EKS처럼 시간당 과금되는 리소스는 확인 후 바로 삭제합니다.
- 액세스 키, 비밀번호, 개인키, `terraform.tfstate`, 비밀이 담긴 `*.tfvars`는 절대 커밋하지 않습니다.
- 결제 알림(AWS Budgets)을 소액으로 설정해 둡니다.
