## 목표 (이 단계가 끝나면 말할 수 있어야 하는 것)
- "Terraform으로 VPC를 퍼블릭/프라이빗으로 나누고, 업데이트 파일 저장소를 외부에서 직접 접근할 수 없게 설계했다."
- "IaC 보안 스캔을 CI에 넣어서 잘못된 설정은 배포 전에 막는다."

## 완성 아키텍처
```
VPC (10.0.0.0/16)
├─ Public Subnet  (AZ-a, AZ-c) ── Internet Gateway, NAT Gateway(테스트할 때만)
└─ Private Subnet (AZ-a, AZ-c) ── 업데이트 서버가 들어갈 자리 (2단계)
S3 버킷 (업데이트 파일): 퍼블릭 차단, 암호화, 버전 관리, VPC Endpoint로만 접근
IAM: 최소 권한 역할
CI: GitHub Actions에서 terraform fmt/validate + Checkov 스캔
```

## 비용·보안 주의
- **NAT Gateway는 켜져 있는 시간만큼 과금.** 실습이 끝나면 바로 삭제.
- 작업이 끝날 때마다 `terraform destroy`. 결제 알림(Budget)을 소액으로 먼저 설정해 두기.
- 프리티어 조건은 계정 생성 시기에 따라 다르니 AWS 콘솔에서 직접 확인.
- 액세스 키는 `~/.aws/credentials`에만. 레포에 절대 넣지 않기.
